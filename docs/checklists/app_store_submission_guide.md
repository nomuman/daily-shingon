## D. 提出後対応フェーズ

### D1. 審査状況の確認方法

| 状況           | 確認方法                                  | 所要時間の目安 |
| -------------- | ----------------------------------------- | -------------- |
| **審査待ち**   | App Store Connectのステータス表示         | —              |
| **審査中**     | メール通知またはApp Store Connectで確認   | 通常1〜3営業日 |
| **承認**       | メール通知 + ステータス「承認済み」       | —              |
| **リジェクト** | メール通知 + 解決が必要な項目が表示される | —              |

**確認頻度:**

- 提出後、1日1回程度App Store Connectを確認する
- 審査担当者からの電話（緊急時）に備え、電話を受けられる体制を整える

### D2. リジェクト時の対応フロー

#### ステップ1: リジェクト理由の理解

1. 通知メールに記載された**Guideline番号**を確認
2. App Store Connect の「解決が必要」セクションで詳細を読む
3. 審査担当者のコメント（スクリーンショットや動画が添付されている場合あり）を確認

#### ステップ2: 対応方針の決定

| パターン                   | 対応方法                                                           |
| -------------------------- | ------------------------------------------------------------------ |
| **バグ修正**               | コードを修正 → 新しいビルドをアップロード → 再提出                 |
| **メタデータ修正**         | App Store Connect上で直接修正 → 再提出（ビルド変更なし）           |
| **ガイドライン解釈の相違** | 審査用メモで誠実に説明 → 再提出 / 場合によりAppeal（異議申し立て） |
| **新規機能追加の要求**     | 要件を実装 → 新しいビルドをアップロード → 再提出                   |

#### ステップ3: 再提出

1. 修正が完了したら、App Store Connectで「**審査に送信**」または「**回答**」をクリック
2. 修正内容を簡潔に記載（審査担当者への返信として）
3. ビルドを変更した場合は新しいビルドを選択

#### まいにち真言で想定されるリジェクトと対策

| 想定リジェクト               | 対策                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| 「宗教的コンテンツの誤解」   | 説明文・審査用メモで「教育的・実践的サポートツール」であることを明記 |
| 「プライバシーポリシー不備」 | URLが有効で、収集データがNutrition Labelsと一致しているか確認        |
| 「デモアカウント無効」       | 審査期間中はデモアカウントを無効化しない                             |
| 「通知の説明不足」           | Info.plistの通知権限説明文が適切か確認（Expoのデフォルトで対応）     |
| 「UIが最新でない」           | スクリーンショットが最新ビルドのUIを反映しているか確認               |

### D3. 承認後のリリース設定

#### ステップ1: リリースタイミングの選択

審査が承認されると、以下のリリースオプションから選択できる：

| オプション       | 説明                                                   | 推奨ケース                                      |
| ---------------- | ------------------------------------------------------ | ----------------------------------------------- |
| **手動リリース** | 承認後、自分で「公開」ボタンを押すまでリリースされない | ✅ **推奨**。リリース日をコントロールしたい場合 |
| **自動リリース** | 承認後、自動的にApp Storeで公開される                  | すぐに公開したい場合                            |
| **予約リリース** | 指定した日時に自動公開される                           | マーケティング告知と日時を合わせたい場合        |

#### ステップ2: リリース後の確認

- [ ] App Storeでアプリが検索できるようになる（公開後数分〜数時間）
- [ ] アプリページの情報（説明文・スクリーンショット）が正しく表示される
- [ ] ダウンロード後、アプリが正常に動作する
- [ ] サポート連絡先（メール・URL）が機能している

#### ステップ3: 初期モニタリング

| 項目                   | 確認方法                               | 期間                |
| ---------------------- | -------------------------------------- | ------------------- |
| **クラッシュレポート** | Xcode → Organizer → Crashes            | リリース後1週間毎日 |
| **レビュー・評価**     | App Store Connect → 「評価とレビュー」 | リリース後毎日      |
| **ダウンロード数**     | App Store Connect → 「Appの分析」      | リリース後毎日      |
| **重大バグ報告**       | サポートメール・SNSなど                | 随時                |
